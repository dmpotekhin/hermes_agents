# План: подключить Perplexity в Hermes как модель + разобраться с FireClaw

## Goal
Сделать Perplexity (sonar-модели) доступным как опциональный алиас модели в этом профиле Hermes (не меняя дефолт), дать честную справку о том, что Perplexity API — платный, и объяснить, что такое FireClaw и требует ли он денег.

## Current context / assumptions
- Активный профиль: `developer`, реальный home = `~/.hermes/profiles/developer/`.
- Текущий конфиг: `model.default: Qwen/Qwen3.5-35B-A3B`, `model.provider: huggingface`, `base_url: https://router.huggingface.co/v1`. Дефолт — БЕСПЛАТНЫЙ (HF).

Три пути добавить: `custom` provider, `openrouter` провайдер, или юзерский алиас с собственным `base_url`/`key_env`. Perplexity — OpenAI-совместимый API (`https://api.perplexity.ai`), поэтому подходит конструкция «юзерский алиас с base_url + key_env».
- Perplexity API — ПЛАТНЫЙ (pay-as-you-go, нужна карта). Цены на момент планирования (web_search, источник aipricing.guru / Perplexity docs):
  - `sonar`: $1 за 1M input / $1 за 1M output
  - `sonar-pro`: $3 / $15

  - доп. request fee зависит от размера search context (Low/Medium/High). Бесплатного API-тира НЕТ.
- FireClaw — название трёх РАЗНЫХ проектов; уточняющий вопрос не ответил пользователь (таймаут), поэтому в плане фиксирую ДОПУЩЕНИЕ: пользователь про coding-агент. Он БЕСПЛАТНЫЙ (open-source), но требует СВОЙ ключ LLM (свой API-ключ провайдера) — сами «модели» не входят.
- ⚠️ АЛЬТЕРНАТИВНЫЕ ЗНАЧЕНИЯ FireClaw (если пользователь имел в виду их, план частично не применим — см. Open questions):
  1. fireclaw.app / raiph-ai/fireclaw — security-прокси, защита агента от prompt injection. Open-source, без ключей (общий community-endpoint).
  2. fireclaw.ai — упаковка OpenClaw в единый бинарь/microVM. Open-source, «скачай и запусти», но нужен ключ LLM.
- Файлы, создаваемые/изменяемые планом: только `/Users/dmitrypotekhin/.hermes/profiles/developer/config.yaml` (через `hermes config set`, НЕ руками) и `.env` профиля. Ничего в других профилях.

## Architecture / proposed approach
Не трогаем дефолтную модель. Добавляем Perplexity как именованный юзерский алиас с собственным `base_url` + `key_env` — так он работает в `/model <alias>` и не влияет на HF-дефолт. Ключ держим в `.env` профиля (`PERPLEXITY_API_KEY`), настройку алиаса — в `config.yaml` через `hermes config set`. Подключение вызывает по запросу, без автопереключения. Это самый неинвазивный способ: не требует billing-настройки до первого фактического вызова, и его легко откатить.

## Step-by-step tasks

### Task 0 — Проверить, что Hermes жив и CLI доступен
```bash
hermes --version
```
Ожидаем: строка версии (любая), exit 0. Если команды нет — стоп, сообщить.

### Task 1 — Получить ключ Perplexity (ручной шаг, пользователь)
Perplexity API-ключ создаётся на https://www.perplexity.ai/settings/api (нужен аккаунт + карта, т.к. API платный). Это шаг, который выполнить автоматически нельзя (нужна оплата/аккаунт). После получения ключа он передаётся пользователем; далее — Task 2.

### Task 2 — Добавить ключ в .env профиля (НЕ в config.yaml)
Файл: `/Users/dmitrypotekhin/.hermes/profiles/developer/.env`
Добавить строку:
```
PERPLEXITY_API_KEY=pplx-xxxxxxxxxxxxxxxx
```
Проверка:
```bash
grep -c '^PERPLEXITY_API_KEY=pplx-' /Users/dmitrypotekhin/.hermes/profiles/developer/.env
```
Ожидание: `1` (именованная переменная присутствует). ⚠️ Не хранить сам ключ в config.yaml — secrets только в `.env`.

### Task 3 — Добавить алиас Perplexity через `hermes config set` (не редактировать config.yaml руками)
```bash
hermes config set model.aliases.pplx.sonar model sonar-pro
hermes config set model.aliases.pplx.sonar provider custom
hermes config set model.aliases.pplx.sonar base_url "https://api.perplexity.ai"
hermes config set model.aliases.pplx.sonar key_env PERPLEXITY_API_KEY
```
(За один раз можно объединить как `hermes config set model.aliases.pplx.sonar openrouter/...` — но у нас свой base_url, поэтому набором.) Не использовать короткую форму без base_url: Perplexity отдельного провайдера в таблице не имеет.

Проверка:
```bash
hermes config get model.aliases.pplx.sonar
```
Ожидание: JSON/YAML с `model: sonar-pro`, `provider: custom`, `base_url: https://api.perplexity.ai`, `key_env: PERPLEXITY_API_KEY`.

Примечание: `key_env`/`base_url` в алиасе означает, что ключ резолвится от ХОСТА алиаса, а не переносится от активного провайдера (HF) — это правильное поведение, чтобы не сломать дефолт.

### Task 4 — Дополнительно: синонимы других sonar-моделей (опционально, YAGNI — делать только если нужно)
По умолчанию добавляем только `sonar-pro` (самый используемый). Если захочешь дешёвый `sonar`:
```bash
hermes config set model.aliases.pplx.sonar-lite model sonar
hermes config set model.aliases.pplx.sonar-lite provider custom
hermes config set model.aliases.pplx.sonar-lite base_url "https://api.perplexity.ai"
hermes config set model.aliases.pplx.sonar-lite key_env PERPLEXITY_API_KEY
```
Рекомендация: НЕ делаем, пока не понадобится (YAGNI).

### Task 5 — Проверить резолв алиаса (без потраченных денег, локальный резолв)
```bash
hermes chat -q "сделай health-check, ответь одним словом: ok" --model pplx.sonar --help 2>&1 | head -5 || true
```
Точная релевантная проверка резолва: посмотреть, что подстрока `--model` принимает юзерский алиас. Если CLI ругается «unknown model», проверить Task 3 ещё раз. Реальную отправку запроса в Task 6.

### Task 6 — Реальный тест запроса (единственный шаг с фактическим расходом)
⚠️ Этот вызов ПОТРАТИТ ДЕНЬГИ (платный API). Выполнять только с явного подтверждения пользователя.
```bash
hermes chat -q "скажи одну строку: ты работаешь?" --model pplx.sonar
```
Ожидание: осмысленный ответ модели (не ошибка авторизации/403). При 403/401 — ключ неверный или нет биллинга, вёрнуться к Task 1.

### Task 7 — (если захочешь сделать дефолтом; по умолчанию НЕ делать)

## Risks, tradeoffs, and open questions
- **Платность**: Perplexity API платный (нет бесплатного API-тира). Любой фактический вызов `pplx.sonar*` расходует деньги. Легко забыть и «случайно» переключиться — поэтому дефолт НЕ трогаем.
- **`key_env` vs `api_key`**: используется `key_env` (ссылка на переменную `PERPLEXITY_API_KEY`), чтобы ключ не утекал в config.yaml. Не смешивать с активным провайдером.
- **Прочий расход**: sonar-deep-research и большие search context добавляют request fee сверх токенов.
- **Открытый вопрос — что за FireClaw**: я зафиксировал допущение «Eldergenix (coding-агент)». Если пользователь имел в виду security-прокси или fireclaw.ai — шаги Task 8 не те, и нужен отдельный план установки. Спросить пользователя перед исполнением Task 8.
- **Открытый вопрос — где добавлять**: таймаут на clarify → предположил «в Hermes, эта сессия». Если надо в OpenCode/KiloCode (`~/work-ai-setup`), это другой набор файлов (opencode.json / kilo.jsonc — там base_url провайдера добавляется иначе). Спросить.
- **Открытый вопрос — качество**: предположил «как LLM-модель для чата». Perplexity также используется как поисковый провайдер в плагине `web-search-plus` (уже установлен в ~/.hermes/plugins/web-search-plus, там `PERPLEXITY_API_KEY`/`KILOCODE_API_KEY`), но это ПРО ПАЙДА, не текущая модель. Если цель — поиск, то это другой план.
