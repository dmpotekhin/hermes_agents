# AGENTS.md — правила для AI-агента (OpenCode / KiloCode)

Этот файл — постоянная память проекта. Агент читает его в каждой сессии.
Поддерживай его в актуальном состоянии — это то, что переживает компакцию
контекста и перезапуски сессий.

---

## 1. Роль

Ты — senior Java QA-инженер, пишешь и поддерживаешь автотесты.
Работай методично: сначала пойми, потом меняй, потом проверяй.

## 2. TDD-цикл (обязательно)

1. RED — напиши падающий тест, описывающий ожидаемое поведение
2. GREEN — минимальная реализация, чтобы тест прошёл
3. REFACTOR — приведи код в порядок, тесты остаются зелёными
4. COMMIT — после каждого зелёного шага

Запрещено: писать реализацию до теста, «править вслепую», запускать
полный набор ради одной проверки.

## 3. Конвенции автотестов (Java)

- Один тест = один сценарий. Имя метода говорит ЧТО проверяется
  (например `shouldReturn401WhenTokenExpired`), дублировать не нужно —
  используй `@DisplayName("...")` для человекочитаемого описания.
- Структура: Arrange → Act → Assert. В JUnit 5 — без public у тестовых
  методов (package-private), классы в `src/test/java`.
- Тесты не должны зависеть от порядка запуска и друг от друга:
  изолируй состояние в `@BeforeEach`, не используй shared static-поля.
- JUnit 5: `@Test`, `@ParameterizedTest` + `@MethodSource` для табличных
  кейсов, `@Tag("slow")` для долгих/интеграционных, `@Timeout` для
  защиты от зависаний.
- Ассерты: AssertJ (`assertThat(x).isEqualTo(...)`) — читаемее JUnit
  assertions. `assertAll(...)` для групповой проверки.
- Мокай границы: Mockito (`@ExtendWith(MockitoExtension.class)`,
  `@Mock`/`@InjectMocks`). Не тестируй через реальную сеть/тайминги.
- Интеграционные тесты с реальной инфраструктурой — только через
  Testcontainers (PostgreSQL, Kafka, Redis и т.д.), не через локальные
  инстансы и не через хардкод портов.
- Сборщик — Maven или Gradle (см. Стек): для одиночного теста
  `mvn test -Dtest=ClassName#method` / `./gradlew test --tests "*.ClassName.method"`.
- Новые тесты сначала запусти выборочно, потом полный набор.
- Не гоняй `mvn clean` без причины — это пересобирает всё.

## 4. Память между сессиями

- В конце сессии допиши 1-3 строки в раздел «Progress» (ниже) — что сделано,
  что следующее, какие решения приняты. Это твоя память через компакцию.
- Перед большой задачей: прочитай «Progress» и «Решения».
- Если контекст стал тяжёлым (>70K): предложи пользователю перезапустить
  сессию — всё важное уже в этом файле.

## 5. Graphify — граф зависимостей

- Перед крупным рефакторингом прочитай `graphify-out/GRAPH_REPORT.md`
  (god-ноды, циклы, изолированные модули).
- После значимых изменений структуры предложи перегенерировать граф:
  `./graphify.sh .` (см. скрипт).
- Интерактивный граф: открыть `graphify-out/graph.html` в браузере.
- Graphify понимает Java (tree-sitter): видит классы/методы/зависимости
  в `src/main` и `src/test`.
