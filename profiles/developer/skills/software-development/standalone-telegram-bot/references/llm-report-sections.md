# Новая секция в LLM-отчёте бота (чеклист по 5 точкам)

Класс задачи: в отчёт, который формирует LLM (валидатор идей и любые похожие
разборы), надо добавить ещё один блок — «кому и за сколько», риски, цены и т.п.
Порядок один и тот же; пропуск любой точки даёт либо `KeyError`, либо секцию,
которой нет в заметке.

## 1. Схема ответа — `swot_analyzer.py`, строка-пример JSON

Новый блок добавить РЯДОМ с существующими (`roi_assessment` и т.п.) и ДО
финального вердикта: модель заполняет то, что видит в примере. Ключи —
snake_case, значения-заглушки по типу (строка/список), чтобы форма была видна.

## 2. Правила системного промпта

Правила пронумерованы подряд — продолжать нумерацию, не вставлять в середину.
В правилах нового блока обязательно оговорить:

- язык/рынок аудитории (напр. русскоязычный: Telegram/VC.ru/Хабр, а не
  LinkedIn/Product Hunt) — иначе модель приносит западные каналы;
- фреймворки, на которые опираться (ICP, метрика ценности, Van Westendorp,
  упаковка/тарифы) — иначе будут общие слова;
- что делать, если блок в реальности нереалистичен: сказать прямо («монетизация
  нецелесообразна»), а не выдумывать цифры.

## 3. Нормализация — `normalize_analysis`

- Достать сырой блок защищённо: `x = source.get("<key>"); x = x if isinstance(x, dict) else {}` — ключа может не быть вообще.
- Текст — `str(...).strip()` + `_shorten` с константой-лимитом; списки — обрезка по `<KEY>_LIST_LIMIT`. Лимиты держать константами рядом с остальными.
- Ключ ВСЕГДА попадает в возвращаемый dict, даже пустым: рендеры читают его напрямую (`data["monetization"]`), а не через `.get()`.

## 4-5. Два рендера

`render_telegram_report`: блок после ROI и ДО вердикта, печатать только если он
непустой — helper вида `_<key>_filled(data) -> bool`, проверяющий и текстовые поля,
и списки. `render_obsidian_body`: та же секция заголовком `## <Название>` в том же
порядке (табличный стиль как у ROI, списки — `-`). Пустой блок не печатать: ответ
без новых данных должен выглядеть как раньше, не хуже.

## 6. Настройки — `validator_service.py`

- Поле в `IdeaValidatorSettings` с дефолтом + строка в `read_iv_settings(...)`: `field=_env_str("IV_<NAME>", default)` (есть также `_env_int`/`_env_bool`).
- Внешний контекст (файл с описанием продукта/бренда) — отдельный модуль-загрузчик рядом с сервисом: нет файла или пустая строка → `""`, обрезка по лимиту, никаких исключений наружу.
- В промпт прокидывать параметром `build_prompts(..., <param>=...)` — keyword-only с дефолтом, чтобы существующие вызовы и 30+ старых тестов не поехали.

## 7. Тесты — новый файл `tests/test_<тема>.py`

Минимальный набор, все без сети (httpx-клиент и `call_chat` замоканы):

1. промпт содержит ключ секции и её фреймворки;
2. контекст подставляется при наличии и блока нет при отсутствии;
3. загрузчик контекста: файл есть / файла нет / обрезка;
4. нормализация режет списки и не падает без ключа;
5. оба рендера печатают секцию на заполненных данных;
6. **обратная совместимость**: ответ LLM БЕЗ нового ключа рендерится как раньше — это единственный тест, который ловит `KeyError` в рендере.

Ассерты на рендер брать из фактического формата строк: эмодзи-префиксы входят в
строку (`🎯 Вердикт: 🧪 PROTOTYPE-FIRST`), иначе тест падает на верной реализации.

## 8. Финал

`.env.example` + строка в таблице env в `README.md`; прогон
`./.venv/bin/python -m pytest tests -q`; credential-scan; коммит.
НЕ ЗАБЫТЬ перезапустить бота после коммита: иначе новая секция проверяется на
старом коде и «ничего не изменилось» выглядит как баг (см. раздел про запуск в
SKILL.md).

## Контекст продукта как отдельный артефакт

Файл-контекст (`.agents/product-marketing.md`: кто я, аудитория, монетизация,
позиционирование) держать с пометками TODO на то, чего агент не знает: промпт
получает файл как есть, и TODO уезжает в модель. Пустой файл — валидное состояние,
загрузчик обязан его пережить.
