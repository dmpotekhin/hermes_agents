# GitHub Search: искать готовое решение до того, как писать код

Класс задач: «есть ли уже готовое?» — перед разработкой фичи, при выборе
форкать / писать с нуля / купить. Один запрос на идею, ответ уходит в LLM как
фактура.

## Запрос

- `https://api.github.com/search/repositories?q=<query>&sort=stars&order=desc&per_page=N`;
  токен опционален — header `Authorization: token <TOKEN>`; без него ~10
  запросов в минуту на IP, одного хватает.
- Всегда добавляй квалификатор `in:name,description,readme`. Без него по той же
  идее приходит 0-3 нерелевантных результата, с ним — десятки, среди которых
  находится реальный аналог с нужным стеком и лицензией.
- GitHub склеивает слова логическим И, поэтому длинный запрос часто даёт ноль.
  Держи цепочку от узкого к широкому и останавливайся на первом непустом:
  4 слова → 3 → 2, каждый с квалификатором. Одно слово не пробовать: это уже не
  поиск, честнее вернуть «готовых решений не нашлось».
- Смысловые слова идеи дают лучший результат в количестве 3. Русские ключи
  работают слабо (мало репозиториев с русскими именами и описаниями), общие
  латинские токены (`telegram`, `bot`) — слишком размытые; вместе они
  покрывают и локальные поделки, и популярные проекты.
- Дефис GitHub трактует как минус-исключение: запрос `idea-validator` вернул
  мусор вместо профильных репозиториев — вырезай дефисы и служебные символы
  перед склейкой запроса.

## Фильтры ответа

Выдача отсортирована по звёздам, и верх занимают не решения, а подборки.
Отсеивай ДО того, как отдать список модели:

- кураторские списки и обучающие материалы: `awesome*`, `public-apis`,
  `free-programming`, `cheat[-_ ]?sheet`, `шпаргалк`, `interview`, `tutorial`,
  `roadmap`, `curated` — репозитории на сотни тысяч звёзд, в README которых
  встречаются любые слова запроса;
- профильные репозитории `owner/owner` (README профиля: 0 звёзд, пустое
  описание).

Проси пул в 2-3 раза больше нужного (`per_page = limit * 3`) и обрезай после
фильтра — иначе топ-5 снова займут подборки.

## Что отдавать дальше

Карточка репозитория: `full_name`, `html_url`, `stars`, `description`,
`language`, лицензия (`license.spdx_id`), `pushed_at` (активность), `archived`.
Лицензия и активность решают рекомендацию: MIT/Apache в живом репозитории →
«форкать», GPL в заброшенном → «писать с нуля».

## Ловушки

- Поиск без токена может отдать 403/429 — это лимит, а не провал идеи: покажи
  «поиск временно недоступен» и продолжи анализ без аналогов (graceful
  degradation), не поднимая исключение наружу.
- Пустой результат — валидный вывод «готовых решений нет», и он должен дойти до
  модели именно так, а не как ошибка инструмента.
- Ссылку на конкретный репозиторий из текста идеи разбирай отдельной веткой
  (`owner/repo` из URL) — один точечный запрос к API точнее любого поиска.
