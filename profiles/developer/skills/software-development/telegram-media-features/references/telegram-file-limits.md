# Лимиты больших медиа в Telegram-боте

Класс задач: бот должен принимать медиа больше 20 МБ (видео/аудио/документы из чата).

## Два разных лимита — не путать

1. **Своя проверка** (`MAX_VIDEO_MB`/`max_upload_mb` и т.п.) — сравнивает размер, заявленный в апдейте, и защищает от лишнего скачивания.
2. **Реальный потолок транспорта** — облачный `api.telegram.org` отдаёт боту файл через `getFile` максимум до 20 МБ. Свою проверку можно поставить хоть 500 МБ — скачивание всё равно упадёт с `Bad Request: file is too big`.

Следствие: менять лимит без локального API-сервера нельзя молча. Минимум — предупреждение при старте; лучше — отдельный понятный текст ошибки на «too big» (иначе пользователь видит только «что-то пошло не так» — именно в обработчике `TelegramBadRequest`).

## Что меняет локальный Bot API server

Официальный сервер `telegram-bot-api` (исходники Telegram, tdlib) запускается на своей машине с флагом `--local`; бот подключается к `http://127.0.0.1:8081` вместо облака.

| | облако | локальный сервер (`--local`) |
|---|---|---|
| скачивание файла боту | до 20 МБ | без лимита |
| отправка файла от бота | до 50 МБ | до 2000 МБ |
| транспорт | CDN Telegram | локальный диск |
| креды | только токен бота | токен бота + `api_id`/`api_hash` аккаунта (my.telegram.org) |
| отказоустойчивость | за Telegram | ты сам: сервер упал → бот молчит целиком |
| диск | — | кэш файлов на диске, растёт |

Установка: **готовность brew-формулы не предполагать** — сначала `brew info telegram-bot-api`; иначе сборка из исходников (tdlib, долго) либо контейнер `aiogram/telegram-bot-api` с `TELEGRAM_LOCAL=true`. Ветку выбирать по факту проверки, а не по памяти.

## Порядок внедрения (по возрастанию риска)

1. Конфиг: поднять лимит в `.env` И в `.env.example`, поправить README (там лимит часто продублирован прозой — иначе документация становится ложью).
2. Стартовое предупреждение — чистая функция `warning(max_mb, api_base) -> str | None`: тестируется без Telegram-объектов.
3. Сессия — чистая функция `build_session(api_base) -> AiohttpSession | None`; пустой `BOT_API_BASE` → `None` и прежнее облачное поведение. Точка подключения — `Bot(token=..., session=...)`.
4. Текст ошибки — чистая функция `download_error_message(text, max_mb)`: при `"too big"` объяснить и предложить ссылку, иначе прежний текст. Пользовательские тексты держать в принятом в проекте месте (в tg-transcriber — константы в начале `bot.py` + страж `tests/test_bot_messages.py`).
5. Сервер: launchd-агент с KeepAlive, `BOT_API_BASE` в `.env`, кэш файлов вне репозитория.
6. Живая проверка: сгенерировать файл >20 МБ (`ffmpeg -f lavfi -i testsrc ... -t 600`) и прогнать через бота — в логе не должно быть `file is too big`.

Rollback: убрать `BOT_API_BASE` из `.env` и перезапустить — возврат к облаку одной строкой.

## Обход, который работает без инфраструктуры

Отправка ПО ССЫЛКЕ: файл качает yt-dlp (или прямой HTTP) на стороне бота, Telegram в передаче не участвует и его лимит не применяется вообще. Если у бота уже есть загрузка по ссылке с своим лимитом (в tg-transcriber `YT_MAX_FILE_MB=150`), большой файл просить владельцу кидать ссылкой, а не вложением — это бесплатно и не требует сервера.

## Ключи и гигиена

`api_id`/`api_hash` — креды аккаунта: только в `.env` (файл в `.gitignore`), в чат не выводить, значения секретов не цитировать; перед коммитом — скан секретов.
