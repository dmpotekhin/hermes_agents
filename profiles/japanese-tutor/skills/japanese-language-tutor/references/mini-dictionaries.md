# Тематические мини-словари (для медиа и спецконтекстов)

## Когда создавать

Пользователь может попросить шпаргалку/словарь для просмотра конкретного сериала, аниме, фильма или игры на японском. Например: «составь мне шпаргалку для просмотра покемонов».

Мини-словарь создаётся как отдельный JSON-файл, не смешивается с основным `user_vocab.json`.

## Формат

```json
{
  "info": {
    "description": "Описание — для чего этот словарь",
    "created": "2026-06-24",
    "total_words": 207,
    "categories": ["битва", "команды", "эмоции", "имена", "мир", "фразы"]
  },
  "words": [
    {
      "id": 1,
      "kanji": "ポケモン",
      "hiragana": "ポケモン",
      "romaji": "pokemon",
      "translation": "покемон",
      "category": "герои",
      "note": "Культурная заметка или частота использования"
    }
  ]
}
```

### Поля

| Поле | Обязательно | Описание |
|------|-------------|----------|
| id | да | автоинкремент внутри файла |
| kanji | да | кандзи или катакана/хирагана |
| hiragana | да | чтение |
| romaji | да | латиница |
| translation | да | перевод на русский |
| category | да | раздел/тема внутри мини-словаря |
| note | нет | контекст, cultural note, знаменитая фраза |

### info секция

- `description` — чтобы через год было понятно, зачем этот файл
- `categories` — список разделов (не themes, а именно categories для этого контекста)

## Расположение

Файл кладётся туда же, где `user_vocab.json`:

```
~/.hermes/jp_rag_data/<context>_vocab.json
```

Примеры:
- `pokemon_vocab.json` — 207 слов, 14 категорий (283 SRT)
- `ghibli_vocab.json` — если пользователь запросит словарь для Тоторо
- `drama_restaurant_vocab.json` — для 孤独のグルメ

## Типичные разделы для аниме/дорам

Для аниме-словарей разбивка по категориям:

| Категория | Что включает |
|-----------|--------------|
| **герои** | имена персонажей, названия существ |
| **батл** | глаголы боя, спецприёмы, состояния (победа/поражение) |
| **команды** | повелительное наклонение, короткие фразы |
| **эмоции** | восклицания, часто повторяемые реакции (すごい, やった, 大丈夫) |
| **типы/предметы** | типы покемонов, названия объектов, еда |

Для бытовых дорам (孤独のグルメ):

| Категория | Что включает |
|-----------|--------------|
| **еда** | названия блюд, ингредиентов |
| **заказ** | фразы для ресторана |
| **ощущения** | 美味しい, 辛い, 熱い и т.д. |

## Workflow создания

1. Определить контекст (какое аниме/дораму будет смотреть пользователь)
2. Собрать ключевую лексику: 15-30 слов
   - Повторяющиеся команды и восклицания (самое частое в диалогах)
   - Слова, уникальные для этого контекста (имена, спецтермины)
   - Полезные общие слова, которые пользователь ещё не учил
3. Разбить на категории (3-5 разделов)
4. Создать файл через `write_file`
5. Сообщить пользователю что создано, показать структуру
6. Добавить запись в `README.md` (дерево jp_rag_data/ — одной строкой)
7. Закоммитить и запушить на GitHub

## После создания мини-словаря

- **Общие слова из мини-словаря** (сильный, слабый, крутой, побеждать) — добавить и в основной `user_vocab.json`, так как они пригодятся и вне контекста аниме
- **Контекстно-зависимые слова** (ポケモン, サトシ, ピカチュウ) — оставить только в мини-словаре, в основной словарь не добавлять
- В основном словаре для общих слов указать источник: `note: "из шпаргалки Pokémon"`

## Автоматическое извлечение из SRT-субтитров

Когда у пользователя есть SRT-файлы с японскими субтитрами к сериалу/аниме, можно построить **большой, проверенный субтитрами** словарь (200+ слов).

### Принцип

Две проблемы без японского токенизатора:
1. В японском тексте нет пробелов — нельзя просто split()
2. Разбивка по границам character type даёт фрагменты (части имён, прилипшие частицы)

**Решение — «курированный словарь + longest-match»:**
- Сначала составляется CORE-словарь с проверенными переводами (100-250 слов)
- Затем каждая строка из SRT проверяется на вхождение этих слов
- Самые длинные совпадения имеют приоритет (longest match)
- Считается, сколько раз каждое слово встретилось в реальных диалогах
- Результат сортируется по частоте

### Структура скрипта

Скрипт `scripts/build_media_vocab.py` состоит из четырёх шагов:

```
1. PARSING  — извлечение японского текста из SRT
2. SCANNING — поиск курированных слов в тексте
3. FILTERING — отсев шума, фрагментов, стоп-слов
4. OUTPUT — JSON + markdown phrasebook
```

### Шаг 1: Парсинг SRT

SRT-формат:
```
1
00:00:03,586 --> 00:00:06,923
Текст субтитра на японском
```

**Что нужно удалить:**
- Номера строк (только цифры)
- Таймкоды (содержат `-->`)
- Строки с ♪～♫♬ (музыка)
- Звуковые эффекты в скобках: （音楽）, （拍手）
- Фуригана в скобках: 攻撃(こうげき) → 攻撃

```python
def extract_text_from_srt(filepath):
    texts = []
    with open(filepath, 'r', encoding='utf-8-sig') as f:
        content = f.read()
    for line in content.split('\n'):
        line = line.strip()
        if not line or line.isdigit() or '-->' in line:
            continue
        if all(c in '♪～♫♬' for c in line):
            continue
        if re.match(r'^[（(][^）)]*[）)]$', line):
            continue
        # Normalize
        text = unicodedata.normalize('NFKC', line)
        text = re.sub(r'[（(][^）)]*[）)]', '', text)  # remove furigana
        if len(re.findall(r'[\u3040-\u9fff\u30a0-\u30ff]+', text)) < 2:
            continue
        texts.append(text.strip())
    return texts
```

### Шаг 2: Составление CORE-словаря

Это самый важный шаг. Словарь пишется вручную — в формате:

```python
CURATED_VOCAB = [
    (kanji_or_word, hiragana_reading, translation, category),
    ("攻撃", "こうげき", "атака", "битва"),
    ("ポケモン", "ポケモン", "покемон", "мир"),
    ("すごい", "すごい", "Потрясающе!", "эмоции"),
]
```

**Категории (пример для аниме):**
- `имена` — персонажи
- `покемоны` — названия существ (для покемонов)
- `мир` — объекты мира (ジム, ポケモンセンター)
- `битва` — боевая лексика
- `команды` — повелительное наклонение
- `эмоции` — восклицания
- `фразы` — бытовая лексика
- `глаголы` — простые глаголы
- `прил` — прилагательные
- `звуки` — ономатопея
- `команда_R` — специфичная для сюжета группа
- `места`, `время`, `предметы` — бытовые категории

Для бытовых дорам категории другие:
- `еда`, `заказ`, `ощущения`

### Шаг 3: Longest-match поиск

Для каждой строки текста перебираем курированные слова (от самых длинных к коротким):

```python
def find_words(text, known_words):
    remaining = text
    while remaining:
        best = None
        for kw in sorted(known_words, key=len, reverse=True):
            if remaining.startswith(kw):
                best = kw
                break
        if best:
            results.append(best)
            remaining = remaining[len(best):]
        else:
            remaining = remaining[1:]
    return results
```

### Шаг 4: Дополнительные слова

После основного сканирования — найти катакана-слова 3+ символов, которых нет в CORE:

```python
extra = re.findall(r'[ァ-ヺー]{3,}', full_text)
# Отфильтровать уже известные, отсортировать по частоте
```

Это даёт новые имена покемонов/персонажей из поздних серий.

### Создание phrasebook

Для пользователя генерируется markdown-файл:
```
# 🎬 Pokémon Phrasebook

## ⚔️ битва
| Кандзи | Хирагана | Перевод | В субтитрах |
|--------|----------|---------|-------------|
| 攻撃 | こうげき | атака | ✅ ×513 |
| ... | ... | ... | ... |
```

### ⚠️ Pitfall: фрагменты имён

Короткие катакана-слова (<4 символов) часто оказываются фрагментами:
- `チョッゲ` = фрагмент ゲンガー + эффект
- `ケモン` = фрагмент ポケモン
- `ダネ` = фрагмент フシギダネ

**Фильтр:** одно- и двухсимвольную катакану не включать в словарь. Трёхсимвольную — проверять вручную.

### ⚠️ Pitfall: pip-таймаут

`pip3 install janome` может таймаутиться (медленная сеть). Janome — чистая Python-библиотека без системных зависимостей, но её установка может занять >60 секунд.

**Workaround:** не нужна. Подход curated-first работает без токенизатора.

## Когда НЕ создавать мини-словарь

- Если пользователь просто перечислил слова из урока JLPT — они идут в `user_vocab.json`
- Если слов меньше 5 — можно просто списком в диалоге
- Если пользователь просит «переведи эту фразу» — перевод в диалоге, не файл
